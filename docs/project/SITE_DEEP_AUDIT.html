Basse / dette

Verdict. Le design system existe et est déjà bien appliqué sur About et ServiceDetail (dev). Le shell (Layout, Navbar, Footer), Home et les outils (Estimateur, Brief) le contournent massivement : ~731 hex dans src/app, CTA plum recopié dans 9+ fichiers, trois dialectes visuels encore actifs. Côté copyright, seul About est validé (14 juil. 2026) ; le parcours Accueil → Services → Contact répète les mêmes promesses et CTAs. Côté code, Home.tsx (3008 L) et ~4950 L de primitives UI mortes dominent la dette.
1

Ce qui est solide

tokens.css sémantique + dark, helpers PAGE_MAIN / SectionEyebrow / PageHero, About en référence 0 hex, ContactForm partagé Home/Contact, CMS localized() central.

2

Ce qui fuit

Hex Tailwind arbitraires, copy inline Estimateur/Brief (~152 ternaires), localized shadowée 3×, nested <main>, PageHero sous-adopté, shadcn quasi inutilisé.

DS-01Critique

Shell Layout hors design system

Layout.tsx:34

Le conteneur racine hardcode bg-[#fcf9f8], text-[#1c1b1b], dark:bg-[#13100f], selection hex — alors que bg-surface-page / text-text-primary existent et gèrent déjà le dark via .dark dans tokens.css.

Fix recommandé : migrer le shell une fois ; toute la cascade hérite correctement.

DS-02Critique

Footer 100 % hex — 0 token sémantique

Footer.tsx (~19 lignes hex, 0 usage surface/text tokens)

Surfaces, textes, hovers, dark et eyebrows tracking-[3px] text-[#854d63] sont tous manuels. SectionEyebrow n’est pas utilisé.

Fix : même migration que About ; eyebrows → composant partagé.

DS-03Critique

CTA plum dupliqué au lieu de bg-action-accent

Navbar, Services, Estimator, ErrorPage, NotFound, RouteErrorBoundary…

bg-[#854d63] hover:bg-[#6a364b] dark:bg-[#d79caf] dark:text-[#1c1415] dark:hover:bg-[#f0adc4]

Équivalents tokens déjà prêts : bg-action-accent, hover:bg-action-accent-hover, text-text-on-strong (dark redéfini dans .dark).

Fix : extrait PrimaryCta / classes utilitaires une seule fois ; supprimer les 9+ copies.

DS-04Haute

Aligné docs/archive/UI_AUDIT.md — non résolu

Le carnet peut garder une hiérarchie documentaire, mais ses contrôles UI (filtres, textes, bordures) devraient partager les tokens de surface.

.dark redéfinit déjà --surface-*, --text-*, --border-subtle. Les fichiers re-spécifient des hex dark et des opacités blanches, ce qui casse la cohérence et complique tout ajustement de palette.

CP-03Haute

CTAs contact non différenciés sur le parcours

Même destination, même intention. L’estimateur (/estimer-mon-projet) et le brief client restent hors du fil principal (méga-menu seulement).

Home hero → manifesto → about teaser → services

Champ lexical saturé : clarté / structure / cohérence / régularité. About page a été nettoyée ; le tunnel amont ne l’a pas été. Le lecteur avance sans gagner de nouvelle information.

3. Écriture accessible

AW-01Critique

Fallback silencieux EN → FR dans localized()

src/cms/types.ts:216–222
return value[locale] || value.fr || value.en || fallback;

En locale en, un champ sans anglais affiche le français sans signal. Combiné à publishLocales: "fr" (témoignages, Carnet, CV), l’expérience EN devient un patchwork invisible pour l’éditrice.

Fix : badge « Traduction à venir » / exiger EN à la publication / ne pas tomber sur FR silencieusement en preview publique.

AW-02Haute

Jargon et phrases denses (Services)

i18n services · pages détail

« Analyse sémantique et graphique », « Roadmaps éditoriales », « objectifs business », « Notion prêts à l’usage ». Blocs de 40–50 mots. Pour une écriture accessible : une idée par phrase, résultat client d’abord, jargon en second.

AW-03Haute

Erreurs Brief EN aplaties + Contact = langue du navigateur

ClientBrief.tsx:245 · ContactForm.tsx

Brief : en anglais, tous les codes d’erreur → « Something went wrong… ». Contact : validationMessage HTML5 suit la langue OS, pas portfolio-lang.

AW-04Haute

Liens / CTA peu descriptifs

Carnet « Découvrir » · cartes blog « Lire l’article »

« Découvrir » n’indique ni Google Books ni nouvel onglet. Les libellés génériques nuisent aux lecteurs d’écran qui naviguent par liste de liens.

AW-05Moyenne

Langage exclusif / biais

CV « Jeune professionnelle » · cibles « Entrepreneurs / Porteurs »

Signal d’âge dans le CV ; génériques masculins sur les cibles services. About validé conserve « porteurs de projets » (nuance mineure). Accueil : « Coffee lover » en anglais dans un trio FR.

AW-06Moyenne

Hiérarchie titres (About & Services)

About SectionEyebrow en <p> · ServiceDetail présentation en <h2>

Les labels de section About ne sont pas exposés comme titres. À l’inverse, du corps est promu h2 sur les services. Impact structure documentaire (TOC lecteur d’écran) sans changer le fond validé.

AW-07Moyenne

HydrateFallback FR-only

routes.tsx:28 « Chargement… »

Flash français pour les visiteurs EN pendant le lazy-load des routes.

CQ-01Critique

Monolithe Home : coût premier chargement

  • ~26 localized() + patterns usingCms ? … : t() qui devraient vivre dans des adapters

CQ-02Critique

Nested <main> généralisé

Layout.tsx:46–48 + ~15 pages

Layout wrappe l’Outlet dans <main> ; About, Contact, Blog, Services, Cv, Brief, etc. rendent un second <main>. Home est le seul outlier cohérent. Landmark unique requis pour l’a11y.

CQ-03Critique

~4950 lignes de primitives UI mortes

src/app/components/ui/*

Usages hors kit : slider, tooltip, cn. ~45 autres modules (button, dialog, sidebar 726 L, chart, carousel…) = 0 import public/admin utile — plus deps Radix / cmdk / vaul / recharts / embla inutilisées.

Fix : purger ou isoler dans un package non bundlé ; alléger package.json.

CQ-04Haute

i18n contournée : ~152 ternaires inline

58× locale === "fr" · 94× isEnglish ? · DesignBrief 72 strings FR-only

Estimateur et Brief portent leur copy dans le composant ({ fr, en }) au lieu de t() / CMS. Incohérent avec le reste du site ; rend les passes rédac TickTick plus difficiles.

6. Vagues recommandées (sans exécution)
