4. Findings — Critique

À traiter avant toute exposition production des pages dynamiques de dev, et avant d’élargir l’accès Auth.

C1

Soft-404 blog : un slug invalide affiche un autre article

Critique
SEORoutingContenu

Fichier : src/app/pages/BlogArticle.tsx (~L53) — posts.find(...) ?? posts[0]

Preuve code (dev). Si le slug n’existe pas, le premier article publié est servi en HTTP 200 avec ses meta SEO. Les crawlers indexent du contenu sous une URL fantôme.

Signal production / main. Confirmé le 27/07/2026 sur /blog/this-slug-should-not-exist-xyz → article « Case study: rebuilding visibility… » (HTTP 200, title de l’article).

Correctif recommandé. Si aucun match → NotFoundPage / réponse 404 + noindex. Ne jamais fallback sur posts[0].

C2

Soft-404 services : un slug inconnu affiche le premier service

Critique
SEORoutingSpécifique à dev

Fichier : src/app/pages/ServiceDetail.tsx (~L72–73) — même pattern ?? services[0]

Preuve code (dev). La branche empty (~L86) ne se déclenche que si la liste est vide. Un mauvais slug sert le premier service + SEO override incorrect. Miroir aussi dans services-dev/ServiceDetailPage.tsx.

Signal production / main. Sur main, les services sont encore un placeholder (« The services are taking shape »). Le soft-404 devient critique dès le merge des pages dev.

Correctif recommandé. 404 réelle si slug (après alias) introuvable ; ne pas utiliser services[0] comme secours.

C3

Tout utilisateur Supabase Auth = éditeur CMS complet

Critique
SécuritéCMSRLS

Migrations : 20260610194517_editorial_workflow.sql, 20260610195227_harden_cms_rls.sql — policies auth.uid() is not null

Preuve. Aucun allowlist email / claim app_metadata.role / table cms_editors. Un compte Auth créé (signup, invite, fuite credential) peut lire/écrire documents, briefs, médias et publier.

Correctif recommandé. Désactiver signup public ; policies basées sur rôle éditeur ; documenter dans SECURITY.md la liste des comptes autorisés.

C4

Écriture directe possible sur cms_public_documents

Critique
SécuritéCMS

Grants insert, update, delete sur cms_public_documents pour authenticated

Preuve. Un client authentifié peut contourner cms_publish_document / validation UI et pousser un snapshot public arbitraire immédiatement.

Correctif recommandé. revoke insert, update, delete pour authenticated ; n’autoriser que les RPC contrôlées (cms_publish_*, trash, etc.).

C5

Formulaire contact sans anti-abus durable

Critique
SécuritéAPICoût

api/contact.js — honeypot + validation seulement ; MEMORY ~L291–292

Preuve. Pas de rate-limit IP/email, pas de captcha, pas de proof-of-work. Spam → coût Resend + saturation Gmail. Le projet le reconnaît déjà comme hardening restant.

Correctif recommandé. Rate limit (Upstash / Vercel KV), option Turnstile, alerte seuil ; répondre 200 « fake success » au honeypot (voir aussi M*).

C6

Collecte de données personnelles sans pages légales

Critique
LégalConfiance

Contact, Cal.com, ClientBrief, ProjectEstimator — aucune route Mentions / Confidentialité / RGPD dans routes.tsx

Preuve. Footer et formulaires ne pointent vers aucune politique. PII collectées (email, messages, briefs, pièces jointes).

Correctif recommandé. Pages Mentions légales + Politique de confidentialité FR/EN, liens footer + formulaires, finalité / durée / destinataires / droits.

C7

Insert anonyme illimité sur design_brief_submissions (legacy)

Critique
SécuritéSpam / PII

supabase/migrations/20260620135500_design_brief_submissions.sql ; encore reflété dans schema.sql — for insert to anon with check (true)

Preuve. La clé publishable suffit pour spammer JSON/PII via REST, même si la route UI /services/brief-design redirige vers le nouveau brief client. Policy storage anon upload retirée plus tard, mais insert table reste.

Correctif recommandé. Drop policy / revoke insert anon ; conserver lecture admin ; soumissions uniquement via endpoints serveur rate-limités.

5. Findings — Haute

H1

SEO SPA : meta deep-links uniquement côté client

Haute

index.html + Seo.tsx + rewrite Vercel catch-all

Le shell HTML reste celui de la home FR. Crawl sans JS / previews sociales faibles sur deep links. Fix : prerender/SSR ou meta par route au build pour pages clés.

H2

Pas de hreflang / URLs par langue

Haute

Seo.tsx, i18n.tsx (localStorage portfolio-lang)

Langue client-only ; canonical unique sans locale. Fix : stratégie URL (/en/… ou query) + alternate hreflang + x-default.

H3

Sitemap incomplet

Haute

public/sitemap.xml

Pages statiques seulement. Absents : /services/:slug, /blog/:slug, /estimer-mon-projet, briefs. Fix : génération depuis CMS publié + lastmod.

H4

/dashboard indexable

Haute

public/robots.txt — Allow: / ; pas de noindex admin

Fix : Disallow: /dashboard + meta robots noindex dans AdminApp.

H5

404 SEO mappé comme « home »

Haute

src/app/seo/fallbackSeo.ts — pathnameToSeoPageKey

Chemins inconnus → clé home ; title/description home sur 404. Fix : clé notFound + noindex.

H6

Lien 404 cassé vers /#projects

Haute

NotFoundPage.tsx ~L43

Home a #home, #services, #testimonials, #contact — pas #projects. Label i18n dit « Explore services ». Fix : /services ou /#services.

H7

Landmarks <main> imbriqués

Haute

Layout.tsx ~L46–48 + pages About, Blog, Contact, Services, Carnet, CV, etc.

Deux landmarks main (confirmé aussi en a11y tree production). Home est OK (sections seules). Fix : un seul main — Layout ou pages, pas les deux.

H8

Pas de skip link

Haute

Layout.tsx / Navbar.tsx

Aucun « Aller au contenu ». Fix : lien skip focusable avant la nav, cible l’unique main.

H9

ContactForm : erreurs non exposées aux technologies d’assistance

Haute

ContactForm.tsx — labels OK ; pas de aria-invalid / aria-describedby

ClientBrief gère déjà le pattern correctement. Fix : aligner ContactForm sur ClientBrief.

H10

CV et haptics principalement via menu contextuel logo

Haute

Navbar.tsx ~L533–630 ; Footer sans /cv ni /blog

Découvrabilité faible (mobile, clavier, lecteurs d’écran). Fix : entrées footer/menu accessibles ; toggle haptics aussi ailleurs.

H11

CMS autoritaire + champ vide = UI vide

Haute

Home.tsx pattern usingCms ? localized(...) : t(...) ; MEMORY

Une lecture CMS réussie avec champ vide n’utilise plus le fallback i18n. Fix : fallback champ-par-champ si localized vide, ou validation publication stricte.

H12

Flash i18n → CMS au premier paint

Haute

cmsContent.ts — état initial usingCms: false

Flicker copy/SEO possible. Fix : skeleton / attendre CMS avant paint éditorial, ou SSR.

H13

Asset about motion ~6,2 Mo

Haute

Home.tsx + MEMORY (H.264 720×900, preload="metadata")

Poids mobile élevé malgré fallback image. Fix : variante compressée / poster-only mobile / lazy mount hors viewport (sans descendre sous ~720×900 pour le rendu retina).

H14

Footer : interception wheel/touch (scroll hijack)

Haute

Footer.tsx ~L591–698

Listeners non-passive pour le reveal shader. Fix : désactiver sous reduced-motion, ne pas bloquer scroll assistif, opt-in plus clair.

H15

Trois dialectes design encore actifs

Haute

Layout/Navbar/Footer/Home (hex) ; Carnet (#EAEAEA…) ; About/ServiceDetail (tokens) — aligné docs/archive/UI_AUDIT.md

Fix : migrer vers tokens.css ; carnet garde sa hiérarchie documentaire mais partage surfaces/texte/bordures.

H16

llms.txt obsolète / inexact

Haute

public/llms.txt

« Carnet » pointe vers /blog ; positionnement et routes carnet/services/estimateur absents ou faux. Fix : aligner sur sitemap + rôle actuel (chargée de communication digitale).

H17

/api/translate : CORS ouvert, plafond faible côté Vercel

Haute

api/translate.js (ALLOWED_ORIGIN défaut *) ; Worker a MAX_TRANSLATION_CHARS

Tout JWT authentifié = quota AI. Fix : origin prod obligatoire, max chars Vercel, rate limit par user, allowlist éditeur.

H18

Preview/prod sans VITE_SUPABASE_* → dashboard démo « login libre »

Haute

src/lib/supabase.ts, LoginScreen.tsx, store.ts demoSignIn

Sans env, toute combinaison email/mot de passe ouvre le dashboard localStorage. Pas de fuite Supabase, mais faux sentiment de prod. Fix : fail closed en build prod si vars absentes.
