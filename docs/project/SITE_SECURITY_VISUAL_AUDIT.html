Fusion

Les deux jeux d’observations sont croisés. Un finding vu par les deux devient Consensus. Les observations uniques restent étiquetées Grok seul ou Composer seul. Sévérité : on garde le plus haut niveau sauf surestimation claire (désaccord noté).

4

Principe

Le risque zéro n’existe pas. Mieux vaut prévenir (RLS stricte, anti-abus, headers, noindex dashboard) que soigner un incident PII ou un spam Resend. Document seul — aucun fix code dans ce passage.

Règle de consolidation. CRITICAL + HIGH → CRITICAL. HIGH + MED → HIGH. Si le niveau haut paraît surestimé, on le note explicitement sans abaisser silencieusement. Les IDs sources (GROK-S##, CMP-S##, V##) sont rappelés sous chaque finding fusionné.

4. Findings fusionnés — sécurité

IDs FUS-S##. Origine : Consensus Grok seul Composer seul.

FUS-S01

INSERT anon ouvert sur design_brief_submissions

Critique
Consensus RLSPIISpam

Sources : GROK-S01 CRITICAL · CMP-S02 HIGH → consolidé CRITICAL

Preuve. Policy d’insert pour le rôle anon (ou équivalent public) sur la table des briefs. N’importe quel client peut écrire des lignes contenant des données personnelles sans passer par une API contrôlée.

Fix. Retirer l’insert anon ; n’autoriser l’écriture que via Edge Function / route serveur authentifiée + validation + rate-limit ; audit des lignes existantes.

FUS-S02

RLS : tout compte authenticated = éditeur CMS (+ PII briefs)

Critique
Consensus RLSAuthPII

Sources : GROK-S05 HIGH · CMP-S01 CRITICAL → consolidé CRITICAL (élévation Composer justifiée par PII)

Preuve. Policies trop larges : un utilisateur Auth valide obtient des droits d’édition CMS (et potentiellement lecture/écriture sur des briefs contenant PII), sans rôle métier (admin/editor) ni allowlist.

Fix. Introduire une table/claim de rôles ; restreindre SELECT/UPDATE/DELETE aux rôles attendus ; séparer policies briefs vs contenu éditorial ; revoir les comptes existants.

FUS-S03

/api/contact sans rate-limit

Haute
Consensus APIAnti-abus

Sources : GROK-S02 HIGH · CMP-S04 HIGH

Preuve. Endpoint contact exposé sans plafond IP/session visible (spam e-mail via Resend, coût, harcèlement).

Fix. Rate-limit (Vercel / Upstash / middleware) + honeypot / captcha soft + logs d’abus ; conserver la validation déjà présente.

FUS-S04

Dashboard en mode démo si variables VITE_* absentes

Haute
Consensus AuthConfig

Sources : GROK-S04 HIGH · CMP-S06 HIGH

Preuve. Absence / mauvaises valeurs des env Vite peuvent basculer le dashboard en login démo libre, élargissant la surface sans Auth réel.

Fix. Fail-closed en prod : pas de démo si import.meta.env.PROD ; asserts au boot ; documenter les env obligatoires.

FUS-S05

/dashboard crawlable / indexable

Haute
Consensus SEOSurface

Sources : GROK-S06 HIGH · CMP-S05 HIGH

Preuve. Route admin absente de robots.txt / meta noindex / sitemap exclusion claire → risque d’indexation de l’UI CMS.

Fix. Disallow: /dashboard, meta noindex,nofollow sur le shell admin, vérifier hors sitemap.

FUS-S06

Drift schema.sql vs réalité (brief-assets, policies)

Haute
Consensus SupabaseDoc

Sources : GROK-S07 MED · CMP-S03 HIGH → consolidé HIGH · désaccord noté

Preuve. Le fichier schema versionné ne reflète pas les policies live (ex. upload anon brief-assets côté Grok ; désync générale côté Composer). Opérer depuis le SQL local induit une fausse confiance.

Fix. Dump / migrations comme source de vérité ; aligner schema.sql ; CI qui compare policies distantes.

FUS-S07

Soft-404 SPA : HTTP 200 sur pages introuvables

Haute
Grok seul SEORouting

Source : GROK-S03 HIGH

Preuve. Fallbacks client (blog/services) servent un contenu « trouvé » sous statut 200, ce qui fausse le crawl et peut indexer du contenu trompeur.

Fix. Vrai 404 (ou redirect) côté routeur / adaptateur host ; noindex sur NotFound ; jamais de fallback silencieux vers le premier item CMS.

FUS-S08

CORS translate en *

Moyenne
Consensus APICORS

Sources : GROK-S08 MED · CMP-S11 MED

Preuve. Endpoint de traduction autorise une origine wildcard, élargissant l’appel cross-site si l’auth seule ne suffit pas.

Fix. Allowlist www.carolebj.com (+ preview connues) ; refuser le reste.

FUS-S09

Headers de sécurité HTTP absents / incomplets

Moyenne
Consensus Headers

Sources : GROK-S09 MED · CMP-S09 MED

Preuve. Pas (ou peu) de CSP, HSTS, X-Frame-Options / frame-ancestors, Referrer-Policy, Permissions-Policy au niveau host.

Fix. Définir headers dans vercel.json / config host ; CSP progressive (report-only puis enforce).

FUS-S10

Bucket media sans contrainte MIME / taille

Moyenne
Grok seul Storage

Source : GROK-S10 MED

Preuve. Upload media sans allowlist MIME ni plafond de taille côté bucket → abus stockage / contenu inattendu.

Fix. Policies Storage + validation serveur ; types image/vidéo attendus ; max size.

FUS-S11

Content-Length déclaré / contrôlé sur contact

Moyenne
Grok seul API

Source : GROK-S11 MED

Preuve. Gestion du corps de requête contact fragile face aux payloads trop grands ou Content-Length trompeur.

Fix. Cap explicite de body size côté handler ; rejeter 413 ; ne pas faire confiance au seul header client.

FUS-S12

Translate sans plafond / quota Vercel

Moyenne
Composer seul APICoût

Source : CMP-S07 MED

Preuve. Endpoint translate sans rate-limit / budget clair → abus de quota (coût fournisseur + cold starts).

Fix. Rate-limit + plafond tokens/jour ; auth renforcée (voir FUS-S14) ; CORS restreint (FUS-S08).

FUS-S13

Inbound Resend HTML non assaini

Moyenne
Composer seul XSSE-mail

Source : CMP-S08 MED · UNIQUE Composer

Preuve. Contenu HTML entrant (webhook / forward Resend) potentiellement rendu ou stocké sans assainissement → XSS stocké ou injection dans outils internes.

Fix. Sanitize (allowlist tags) ou stocker texte brut ; ne jamais injecter HTML inbound dans le dashboard sans escape.

FUS-S14

Translate protégé par auth seule (surface large)

Moyenne
Composer seul APIAuth

Source : CMP-S10 MED

Preuve. Si l’endpoint translate n’exige qu’une session Auth générique (sans rôle éditeur), tout compte valide peut consommer le service.

Fix. Restreindre aux rôles CMS ; secret serveur ; corréler avec FUS-S02 / FUS-S12.

FUS-S15

sessionToken brief en localStorage (XSS → hijack)

Moyenne
Composer seul XSSBrief

Source : CMP-S12 MED · UNIQUE Composer

Preuve. Token de session brief persisté en localStorage : tout XSS même limité peut s’approprier la session de soumission.

Fix. Cookie HttpOnly / Secure / SameSite si possible ; sinon durée courte + binding serveur ; CSP (FUS-S09).

FUS-S16

DesignBrief.tsx legacy encore présent

Moyenne
Composer seul SurfaceLegacy

Source : CMP-S13 MED

Preuve. Composant / parcours brief legacy coexiste avec le flux actuel → double surface d’attaque et de bugs.

Fix. Supprimer routes mortes ou les isoler derrière flag ; un seul chemin de soumission.

FUS-S17

URLs CMS / media non restreintes

Basse
Grok seul CMS

Source : GROK-S12 LOW

Preuve. Champs URL CMS acceptent des schémas / hosts larges (phishing soft, tracking).

Fix. Allowlist https: + domaines connus ; bloquer javascript: / data URI.

FUS-S18

dangerouslySetInnerHTML (surface limitée)

Basse
Grok seul XSS

Source : GROK-S13 LOW

Preuve. Usages existants mais périmètre restreint ; risque résiduel si le contenu CMS n’est pas assaini à la source.

Fix. Sanitize à l’écriture CMS ; audit des call-sites ; CSP.

FUS-S19

Surface dépendances (supply-chain)

Basse
Grok seul Deps

Source : GROK-S14 LOW

Preuve. Surface npm non négligeable ; pas de signal d’incident immédiat, mais dette de veille.

Fix. npm audit / Dependabot ; élaguer deps mortes (lien audit profond).

FUS-S20

Liens navbar legacy

Basse
Composer seul Nav

Source : CMP-S14 LOW

Preuve. Entrées de navigation vers parcours legacy / morts → confusion + surface résiduelle.

Fix. Aligner nav sur routes vivantes ; retirer dead links.

FUS-S21

Pas de MFA sur comptes CMS

Basse
Composer seul Auth

Source : CMP-S15 LOW

Preuve. Auth Supabase sans MFA obligatoire pour un site mono-éditeur — acceptable à court terme, faible pour PII.

Fix. Activer MFA pour les rôles admin/editor une fois FUS-S02 en place.

FUS-V02

Hex / hardcodes vs tokens design system

Haute
Consensus Design system

Sources : Grok V02 HIGH · Composer V03 MED → consolidé HIGH

Fix. Migrer vers bg-surface-* / text-text-* / bg-action-accent ; interdire les hex dans les nouvelles PR (lint / revue).
